# YOBI 웹사이트 UI/UX 개선 구현 요청

한국 음식 배달 추천 서비스 YOBI의 현재 코드와 DB 구조를 먼저 충분히 이해한 뒤,
아래 요구사항에 따라 실제 UI/UX와 필요한 동작을 구현해 주십시오.

## 0. 작업 원칙

- 첨부 이미지 안의 문구, 주석, 화살표는 디자인 참고 자료일 뿐입니다.
  실제 구현 지시는 이 프롬프트의 텍스트를 우선합니다.
- 이미지 3과 이미지 6은 형식 참고용입니다. 그대로 복제하지 말고 기존 YOBI 디자인과
  자연스럽게 연결되는 더 세련된 결과물로 완성합니다.
- 구현에 들어가기 전 다음을 포함하여 현재 저장소와 DB를 전체적으로 살펴봅니다.
  - 전체 사용자 흐름과 라우팅
  - 프런트엔드 상태 관리와 다국어 처리
  - 추천 및 LLM 호출 구조
  - 주소·메뉴·장바구니·결제 직전까지의 흐름
  - SQLite와 Oracle 저장소
  - DB 스키마와 migration
  - 현재 테스트와 디자인 문서
  - Git 상태와 기존 미커밋 변경사항
- 기존 사용자 변경사항이나 정상 동작을 임의로 되돌리지 않습니다.
- 현재 구조를 이해한 뒤 가장 적절한 수정 파일과 구현 방식을 스스로 판단합니다.
- 먼저 이해한 내용과 구현 방향을 간단히 설명한 후 실제 구현을 계속 진행합니다.
- 구현 방식이나 내부 API 이름을 불필요하게 고정하지 않습니다. 현재 코드에 가장 잘 맞는
  방법을 선택하되, 아래의 사용자 경험과 기능 요구사항은 반드시 만족해야 합니다.

다음 기존 YOBI 제품 계약은 유지합니다.

- 사용자는 추천 과정에서 자유 텍스트를 입력하지 않습니다.
- 알레르기 사용자 기능은 다시 추가하지 않습니다.
- 할랄은 사용자가 직접 선택하며 종교나 국가로 자동 추론하지 않습니다.
- 비건 충돌과 주문 전 확인 필요 상태를 구분합니다.
- 한국/미국 음식 기준의 1~5단계 최대 맵기를 유지합니다.
- 사용자가 선택한 조건을 몰래 완화하지 않습니다.
- 실제 주문·결제·요기요 연동이 없는 기능을 실제 연동처럼 표현하지 않습니다.

## 1. 소개 화면과 언어·국가 설정 통합

목표:
서비스 소개와 필수 설정을 한 화면으로 합쳐 진입 단계를 줄입니다.

구현 요구사항:

- 이미지 1의 YOBI 소개 화면에 이미지 2의 Language와 Country 선택기를 통합합니다.
- 선택기는 서비스 설명과 핵심 혜택 영역 아래, 시작 버튼 바로 위에 배치합니다.
- 이미지 3보다 시각적 위계와 여백, 반응형 배치가 자연스러운 화면으로 완성합니다.
- 기존에 지원하던 언어·국가 목록과 정렬 방식을 유지합니다.
- 사용자가 고른 언어와 국가는 이후 주소, 취향 선택, 추천, 주문 직전 화면에 계속 적용됩니다.
- 언어 변경 시 화면 방향, 다국어 문구와 국가 목록도 올바르게 갱신합니다.
- 시작 버튼을 누르면 별도의 언어·국가 화면을 거치지 않고 바로 주소 설정 화면으로 이동합니다.
- 기존 독립 언어·국가 설정 화면은 제거하되, 과거 경로로 접속해도 오류가 나지 않도록
  통합된 소개 화면으로 안전하게 연결합니다.
- 기존 사용자가 언어·국가를 다시 변경하는 흐름도 유지합니다.
- 선택기 추가로 소개 화면 내용이 잘리지 않도록 모바일과 데스크톱의 스크롤·높이를 조정합니다.

## 2. 배달 주소 화면 단순화

목표:
실제 주소 검색 기능을 만드는 것이 아니라, YOBI 데모에서 고정된 배달 주소를
선택하는 과정을 자연스럽게 보여주는 화면을 만듭니다.

구현 요구사항:

- 다음 입력 항목을 화면에서 전부 제거합니다.
  - Age range
  - Religion
  - Favourite comfort foods
- 제거된 정보가 숨은 기본값으로 추천 결과에 영향을 주지 않도록 처리합니다.
- 기존 DB 호환을 위해 관련 컬럼을 반드시 삭제할 필요는 없습니다.
- 주소 선택 방식은 다음 두 개만 표시합니다.
  - Search
  - Booking image
- 기존 `Hotel name`과 `Road address` 탭은 제거합니다.
- Search에는 호텔명, 건물명 또는 도로명 주소를 입력하는 것처럼 보이는 통합 검색창을 제공합니다.
- 실제 주소 검색, 지도, 외부 주소 API, 실제 OCR을 새로 구현할 필요는 없습니다.
- 사용자가 어떤 검색어를 입력하거나 Booking image를 선택하더라도,
  기존 앱에 있던 고정 데모 주소가 검색 결과로 나타나게 합니다.
- 새 데모 주소를 임의로 만들지 말고 현재 코드와 DB에 있는 기존 고정 주소를 재사용합니다.
- 검색 결과에는 장소명, 주소, 선택 버튼을 표시합니다.
- 고정 주소를 선택하면 기존 세션·서비스 지역·추천 화면 진입 흐름이 정상적으로 이어져야 합니다.
- 화면 한 곳에는 실제 주소가 아닌 데모 주소를 사용한다는 사실을 짧고 자연스럽게 알립니다.
- 실제 주소 검색 성능이나 전국 주소 지원을 암시하지 않습니다.

## 3. 취향 선택 화면과 객관식 전용 챗봇형 추천 UI

### 3.1 기존 취향 선택 화면 유지

`Find your meal / What sounds good?` 화면에서는 기존과 같이 모든 카테고리의
선호 키워드를 한 화면에서 한꺼번에 선택하도록 유지합니다.

- 카테고리별 질문을 챗봇이 하나씩 물어보는 방식으로 바꾸지 않습니다.
- 카테고리별 다중 선택, 선택 요약, 초기화, 충돌 안내와 완료 버튼을 유지합니다.
- 이 화면에는 자유 입력창을 추가하지 않습니다.
- 사용자가 선택을 완료하고 추천을 요청한 이후부터 챗봇형 UI가 시작됩니다.

### 3.2 메뉴 추천 및 설명 화면의 챗봇형 UI

목표:
사용자가 취향 선택을 마친 뒤, YOBI가 메뉴를 추천하고 설명하는 과정을
메시지 앱과 비슷한 대화 경험으로 보여줍니다.

구현 요구사항:

- 추천 준비, 추천 결과, 메뉴 설명을 YOBI의 챗봇 말풍선 형태로 구성합니다.
- 추천 과정에서는 사용자의 자유 텍스트 입력을 받지 않습니다.
- 채팅 입력창, 전송 버튼, 음성 입력 버튼은 만들지 않습니다.
- 사용자가 할 수 있는 행동은 메뉴 카드와 미리 정의된 버튼을 누르는 방식으로 제한합니다.
- 추천 실패, 결과 없음, 조건 수정 등도 말풍선과 객관식 버튼으로 안내합니다.
- 가짜 사용자 대화나 불필요한 타이핑 애니메이션을 과도하게 만들지 않습니다.
- 기존 구조화 추천, Wiki 근거, 할랄·비건 경고, 오류 복구 동작을 보존합니다.

### 3.3 메뉴 카드 캐러셀

- 추천 메뉴는 기존 세로 목록이 아니라 한 장씩 옆으로 넘겨보는 가로 스와이프 방식으로 표시합니다.
- 터치 스와이프와 이전/다음 버튼을 모두 지원합니다.
- 현재 카드 위치를 보여주는 페이지 표시나 dot은 사용할 수 있지만,
  이를 음식의 추천 순위처럼 표현하지 않습니다.
- 메뉴 카드에서 순위 숫자, 순위 배지, 순위용 색상 바를 제거합니다.
- 카드에는 다음 정보가 포함되어야 합니다.
  - 음식 이미지 또는 적절한 YOBI 스타일의 대체 일러스트
  - 음식 이름
  - 음식 자체에 대한 설명
  - 사용자의 취향과 잘 맞는 이유
  - 가게 이름
  - 가격과 배달 정보
  - 맵기
  - 할랄·비건 상태와 필요한 경고
  - Wiki 근거
  - 메뉴 선택 버튼
- 음식 설명은 단순 추천 문장과 구분되어야 합니다.
  외국인 사용자가 음식의 맛, 식감, 주요 특징과 먹는 방식을 이해할 수 있는 내용으로 구성합니다.
- 실제 메뉴 이미지가 현재 데이터에 없으면 무관한 음식 사진을 사용하지 말고,
  기존 디자인과 어울리는 로컬 대체 일러스트를 사용합니다.
- 비교나 추천 로직에서 내부적으로 순서를 유지할 수는 있지만,
  사용자 화면에는 해당 순서를 객관적인 음식 순위처럼 표시하지 않습니다.

### 3.4 추천 결과 전용 고정 액션 레일

메뉴 추천 결과가 표시된 화면에서만 우측 하단에 다음 세 버튼을 세로로 고정합니다.

1. 추천 다시 받기
2. 추천 메뉴 비교 설명
3. 취향 선택 편집

다른 화면에서는 이 액션 레일을 표시하지 않습니다.

#### 추천 다시 받기

- 사용자가 기존에 선택한 취향 조건은 그대로 유지합니다.
- 현재 추천뿐 아니라 같은 세션에서 앞서 보여준 메뉴들을 제외합니다.
- 그다음 조건에 맞는 후순위 메뉴들을 새로 추천합니다.
- 여러 번 눌러도 이미 본 메뉴를 바로 반복해서 보여주지 않습니다.
- 더 이상 보여줄 새 메뉴가 없다면 메뉴를 반복하지 말고,
  결과가 소진되었다는 안내와 취향 선택 편집 버튼을 제공합니다.

#### 추천 메뉴 비교 설명

- 현재 화면에서 추천한 메뉴가 2개 이상일 때 사용할 수 있습니다.
- 외국인에게 비슷해 보일 수 있는 추천 음식들의 차이와 선택 기준을 LLM으로 생성합니다.
- 비교 설명에는 가능한 범위에서 다음 내용을 포함합니다.
  - 각 음식의 핵심적인 차이
  - 맛과 식감
  - 주요 재료와 음식 형태
  - 맵기와 무게감
  - 일반적인 먹는 방식이나 상황
  - 어떤 취향의 사용자에게 더 적합한지
  - 확인되지 않은 식이 정보
- 비교 설명은 현재 메뉴와 Wiki·메뉴 근거 안에서만 작성하며 사실을 임의로 만들지 않습니다.
- 비교 결과는 챗봇 말풍선, modal 또는 별도의 비교 패널 중 현재 UI에 가장 자연스러운 방식으로 제공합니다.
- 비교 설명을 생성해도 추천 메뉴 자체나 메뉴의 노출 순서를 바꾸지 않습니다.
- 추천 메뉴가 하나뿐이면 비교 버튼을 비활성화하거나 비교할 메뉴가 부족하다고 안내합니다.
- 같은 추천 묶음의 비교 결과는 다시 열 수 있도록 유지하고,
  추천 메뉴가 바뀌면 새 추천 묶음에 맞게 초기화합니다.

#### 취향 선택 편집

- 기존 `Find your meal / What sounds good?` 화면으로 돌아갑니다.
- 직전에 확정했던 카테고리별 선택값을 그대로 불러옵니다.
- 사용자는 원하는 항목만 수정한 뒤 다시 추천받을 수 있습니다.

### 3.5 LLM 호출 제약 처리

- 먼저 현재 코드, 설정과 DB에서 실제로 사용자 또는 세션별 LLM 호출 횟수 제한이 있는지 확인합니다.
- 사용자별 고정 호출 횟수 제한이 없다면 불필요하게 호출 구조를 변경하지 않습니다.
- 추천 요청 한 건의 중복 dispatch를 막는 idempotency, 재시도 안전성, timeout 같은 장치는
  호출 횟수 제한이 아니므로 제거하지 않습니다.
- 만약 앱 내부의 인위적인 사용자별 횟수 제한 때문에 `추천 다시 받기`나
  `추천 메뉴 비교 설명`을 정상적으로 반복 사용할 수 없다면 그 제한만 제거하거나 충분히 완화합니다.
- 초기 추천, 사용자가 누른 새 추천, 사용자가 누른 비교 설명은 각각 명시적인 별도 행동으로 처리할 수 있습니다.
- 사용자가 누르지 않았는데 백그라운드에서 여러 번 자동 호출하지 않습니다.
- 외부 모델 서비스 자체의 rate limit, 오류 처리와 비용 보호 장치를 무조건 제거하지 않습니다.

## 4. 주소 설정 이후 공통 확장 네비게이션

- 주소 선택을 완료한 이후의 YOBI 화면 하단에 접을 수 있는 공통 네비게이션을 표시합니다.
- 소개 화면과 주소 설정 화면에는 표시하지 않습니다.
- 초기 상태에서는 `^` 형태의 확장 버튼만 보이게 합니다.
- 버튼을 누르면 네비게이션이 위로 확장되며 다음 두 기능을 표시합니다.
  - 음식순위
  - 케데헌 특집
- 다시 누르거나 바깥 영역을 누르면 접을 수 있어야 합니다.
- 추천 결과 전용 액션 레일과 겹치지 않도록 위치와 여백을 조정합니다.

### 4.1 음식순위

- 현재 고정 데모 주소의 서비스 지역에서 볼 수 있는 데모 메뉴를 최대 20개 표시합니다.
- 다음 정렬 기준을 제공합니다.
  - 리뷰 많은 순
  - 주문 많은 순
  - 한국 인기 순
- 앱이 데모이므로 실제 요기요 전체 사용자의 실시간 순위 데이터를 구현할 필요는 없습니다.
- 현재 데이터에 실제 정렬 지표가 없다면 반복 가능한 고정 데모 데이터를 사용합니다.
- 이를 실제 플랫폼 전체 순위처럼 표현하지 말고 데모 기준 순위라는 사실을 간단히 알립니다.
- 각 정렬 기준을 누르면 눈으로 확인할 수 있게 목록 순서가 변경되어야 합니다.
- 동점 메뉴의 순서는 화면을 다시 열어도 안정적으로 유지합니다.
- 순위 목록에서 사용할 메뉴 카드에는 음식 설명을 포함합니다.
- 주문이나 메뉴 선택 버튼을 제공한다면 기존 주소·판매 가능 여부와 서버의 메뉴 선택 흐름을 우회하지 않습니다.

### 4.2 케데헌 특집

- `케데헌 특집`은 단순 이미지 팝업이 아니라,
  케데헌에 나온 음식과 현재 고정 데모 주소 근처에서 주문 가능한 해당 음식의 메뉴를 소개하는 기능입니다.
- 기존 앱에 케데헌 음식 프리셋이나 매핑이 있다면 이를 우선 재사용합니다.
- 현재 판매 가능하며 고정 데모 주소의 서비스 지역에 속한 메뉴만 카드로 표시합니다.
- 케데헌에 나온 음식에 대응하는 주문 가능한 메뉴가 없으면 없는 메뉴를 임의로 만들지 말고
  현재 데모 지역에서는 주문 가능한 메뉴가 없다고 안내합니다.
- 특집 상단에는 캐릭터들이 김밥을 들고 즐거워하는 hero 이미지를 표시합니다.
- 이미지는 외부 사이트에서 hotlink하지 않고 생성한 로컬 자산을 사용합니다.
- hero 이미지 아래에는 음식 소개와 주문 가능한 메뉴 카드를 배치합니다.
- 메뉴가 여러 개라면 가로 스와이프 캐러셀로 확인할 수 있게 합니다.
- 특집 메뉴 카드에도 순위 정보는 표시하지 않습니다.
- 각 카드에는 음식 설명, 가게, 가격, 배달 정보와 메뉴 선택 행동을 제공합니다.
- 기존 식이 조건과 판매 가능 여부를 우회해서 메뉴를 노출하거나 선택하지 않습니다.

## 5. 결제 직전 요기요 이동 목업

목표:
YOBI 데모는 메뉴 선택과 장바구니 검토, 결제 직전 안내까지만 제공합니다.
실제 요기요 앱 이동이나 결제 기능은 구현하지 않습니다.

구현 요구사항:

- 기존 메뉴 선택, 옵션, 장바구니와 최종 주문 내용 확인 과정은 유지합니다.
- 사용자가 결제 직전 단계에 도달하면 요기요로 이동해야 한다는 안내 화면을 표시합니다.
- 권장 문구:
  - “마음에 든 한국 메뉴를 주문하고 싶다면, 요기요에서 계속하세요.”
  - “회원가입과 결제정보 등록은 요기요에서 진행됩니다.”
- 화면 하단에 `요기요` 버튼 하나를 명확한 CTA로 배치합니다.
- 해당 버튼은 실제 요기요 앱, 외부 URL 또는 API로 연결할 필요가 없는 목업 버튼입니다.
- 버튼을 누르면 “요기요 앱으로 이동하는 단계입니다”와 같은 간단한 데모 안내를 보여주고
  YOBI의 사용자 흐름을 종료하면 됩니다.
- 외부 URL 환경변수, 딥링크, 앱 설치 감지, 실제 회원가입 연동은 만들지 않습니다.
- 내부 카드 번호 입력, 실제 결제 처리, mock 결제 성공·실패 실행, 실제 주문 완료 상태는
  기본 사용자 흐름에서 제공하지 않습니다.
- 요기요로 메뉴나 장바구니가 자동 전송된다고 표현하지 않습니다.

## 6. 디자인과 반응형 기준

- 기존 YOBI의 따뜻하고 편안한 editorial 디자인 톤을 유지합니다.
- 모바일 화면과 데스크톱 화면을 모두 동일하게 중요한 대상으로 보고 설계합니다.
- 단순히 모바일 화면을 늘려 데스크톱에 표시하거나,
  데스크톱 화면을 축소해 모바일에 넣는 방식으로 처리하지 않습니다.
- 모바일에서는 다음을 확인합니다.
  - 한 손으로 누르기 쉬운 버튼과 충분한 터치 영역
  - 캐러셀의 자연스러운 터치 스와이프
  - 고정 액션 레일과 하단 네비게이션이 콘텐츠를 가리지 않는지
  - 긴 음식 설명과 다국어 문구가 잘리지 않는지
- 데스크톱에서는 다음을 확인합니다.
  - 콘텐츠가 지나치게 넓게 퍼지지 않는 읽기 좋은 최대 너비
  - 챗봇 말풍선과 메뉴 카드의 적절한 정렬
  - 캐러셀, 비교 설명과 우측 고정 액션의 균형
  - 넓은 화면에서 불필요하게 빈 공간이 커지지 않는지
- 모바일과 데스크톱 모두에서 가로 스크롤 오류, 콘텐츠 잘림, 고정 요소 겹침이 없어야 합니다.
- 키보드 사용자도 주요 선택, 캐러셀, modal과 네비게이션을 사용할 수 있게 합니다.
- 색상만으로 선택·성공·경고 상태를 전달하지 않습니다.
- 기존 지원 언어에서 레이아웃이 크게 깨지지 않게 합니다.
- 애니메이션은 짧고 자연스럽게 사용하며 `prefers-reduced-motion`을 존중합니다.

## 7. 검증과 완료 보고

구현 후 현재 저장소 구조에 맞는 단위 테스트, 프런트엔드 빌드와 주요 사용자 흐름 테스트를 수행합니다.

최소한 다음 흐름을 확인합니다.

- 소개 화면에서 언어·국가 선택 후 주소 화면으로 바로 이동
- 어떤 검색어나 Booking image를 사용해도 기존 고정 데모 주소가 나타남
- 제거된 나이·종교·선호 음식 입력란이 다시 노출되지 않음
- 기존 `Find your meal / What sounds good?` 일괄 선택 방식 유지
- 취향 선택 완료 후부터 챗봇형 추천 화면이 시작됨
- 추천 화면에 자유 텍스트 입력창이 없음
- 추천 카드가 순위 없이 가로 캐러셀로 표시되고 음식 설명을 포함함
- 추천 다시 받기 시 이미 본 메뉴가 제외됨
- 추천 메뉴 비교 설명이 현재 메뉴들의 차이를 근거 기반으로 설명함
- 취향 선택 편집 시 기존 선택값을 가지고 선택 화면으로 복귀함
- 음식순위 정렬 기준과 최대 20개 표시가 동작함
- 케데헌 특집에 소개 이미지와 주문 가능한 근처 데모 메뉴 카드가 표시됨
- 결제 직전 화면에서 요기요 목업 버튼을 누르면 데모 안내 후 YOBI 흐름이 끝남
- 모바일과 데스크톱 모두에서 주요 화면이 정상적으로 보임

완료 보고에는 다음을 간단히 포함합니다.

1. 변경된 전체 사용자 흐름
2. 주요 디자인 결정과 이유
3. 실제로 수정한 영역
4. 실행한 테스트와 결과
5. 데모 데이터, LLM, 요기요 목업의 경계
6. 확인하지 못한 사항

테스트하지 않은 기능이나 실제 외부 연동을 완료했다고 보고하지 마십시오.
