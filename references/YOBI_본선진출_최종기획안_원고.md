## 02. Executive Summary

### YOBI는 외국인을 위한 번역 챗봇이 아니라, 첫 주문 전환을 만드는 제한형 커머스 에이전트다.

#### 문제

한국어가 서툰 사용자는 메뉴의 단어만 번역하면 주문할 수 있는 것이 아니다. 음식의 맛과 양, 제한 식재료, 가게 간 차이, 한국식 옵션과 주소를 동시에 판단해야 한다. 번역되어도 주문 확신은 생기지 않는다.

#### 해법

사용자가 자기 언어로 상황과 조건을 말하면 YOBI가 요기요의 메뉴·옵션·리뷰·배달 가능 구역·장바구니 도구를 호출한다. 후보를 2~3개로 압축하고 문화적 맥락과 근거 상태를 설명하며, 최종 확인까지 한 대화 안에서 연결한다.

#### 4주 MVP

영어 우선, 서울 1개 생활권, 검수 가능한 데모 가게 30곳·메뉴 약 150개. 자연어 탐색, 문화 설명, 식이 위험 근거, 가게 비교, 옵션·요청사항, 주소 확인, 장바구니 미리보기와 목업 결제를 구현한다.

#### 검증 목표

- 첫 주문 확인 과업 완료율 80% 이상
- 주문 확인까지 중앙 소요시간 3분 이하
- 치명적 허위 안심 0건
- 식이 관련 사실 주장 근거 연결률 100%
- 메뉴·가격·필수 옵션 불일치 0건

#### 요기요 가치

요기요가 추진하는 `From Static to Seamless`를 외국어 사용자까지 확장한다. 외국인 첫 주문 완료율을 개선하고, 이후 모든 사용자를 위한 자연어 탐색·근거 기반 리뷰 브리핑·재주문의 기반을 만든다.

## 03. 문제 정의

### 번역되어도 주문은 되지 않는다.

#### 가설 페르소나

**Ayu, 23세, 인도네시아 출신 교환학생**

- 한국 거주 2개월차, 영어 사용
- 돼지고기를 피하고 매운맛에 약함
- 기숙사 주소와 한국식 옵션이 낯섦
- 목표: 15,000원 안에서 따뜻한 국물 한 끼 주문
- 현재 대안: 번역 앱, 익숙한 프랜차이즈 반복, 한국인 친구에게 부탁

#### 첫 주문을 막는 다섯 판단 부담

1. **언어**: 메뉴명·옵션·리뷰를 읽기 어렵다.
2. **문화**: 번역 후에도 맛·향·식감·양을 알 수 없다.
3. **식이 근거**: 할랄·비건·알레르기 정보의 출처와 범위가 불명확하다.
4. **주문 문법**: 곱빼기·사리·수저·요청사항·한국식 주소를 이해해야 한다.
5. **인터페이스**: 필요한 정보가 여러 화면에 흩어져 앱 구조를 학습해야 한다.

#### 핵심 인사이트

외국인이 찾는 것은 외국어 화면만이 아니다. 지금의 실제 해결책인 ‘한국인 친구’가 해주던 **질문, 설명, 위험 확인, 비교, 주문 구성**을 원한다.

`번역 앱 ↔ 배달앱 ↔ 한국인 친구`를 오가던 단절된 흐름을 YOBI 한 대화로 닫는다.

## 04. 시장 기회와 전략적 타깃

### 외국인 시장은 비어 있는 시장이 아니라, 이제 막 열린 경쟁 시장이다.

- **278.3만 명**: 2025년 말 국내 체류외국인, 전년 대비 5.0% 증가
- **90.3만 명**: 유학생 30.9만 + 취업자격 체류자 59.4만. 반복 주문 가능성이 높은 1차 타깃의 인구 프록시
- **1,894만 명**: 2025년 방한 외래관광객. 결제·인증 연동 이후의 2차 확장 시장
- **+300%**: 2025년 12월 배달의민족 글로벌 결제 주문 건수의 전년 동월 대비 증가율. 외국어 배달 수요가 실제 주문으로 이어진다는 시장 신호

#### 타깃 우선순위

1. **MVP — 한국 거주 외국인 유학생·근로자**: 고정 주소, 반복 주문, 선호 메모리와 30일 재주문 검증이 가능하다.
2. **확장 — 단기 방문 관광객**: 해외 결제·게스트 인증·숙소 주소 검증 뒤 호텔 및 게스트하우스 QR로 확장한다.
3. **플랫폼화 — 전체 사용자**: 메뉴 결정 피로, 알레르기 탐색, 자연어 재주문으로 확대한다.

#### 왜 요기요인가

요기요는 2026년 앱 개편에서 탐색 피로를 줄이고 주문까지 끊김 없이 연결하는 `From Static to Seamless`를 선언했다. YOBI는 이 전략을 한국어와 한국 음식 문법이 없는 사용자에게 확장하는 선택형 대화 레이어다.

## 05. 서비스 컨셉

### 대화가 곧 앱이다.

사용자는 기능 위치를 배우지 않고 자기 언어로 상황과 조건을 말한다. YOBI는 대화 상태에 따라 검색·설명·근거·비교·옵션·주소·장바구니 도구를 호출한다. 탐색과 질문은 자연어로, 비교와 최종 선택은 리치 카드로 처리한다.

#### 한 대화, 여섯 번의 결정

1. **Understand** — 상황·예산·맛·제외 재료를 해석한다.
2. **Shortlist** — 배달 가능한 후보를 2~3개로 압축한다.
3. **Explain** — 맛·식감·양을 사용자가 선택한 익숙한 음식 기준으로 설명한다.
4. **Ground** — 가게 확인 정보, 위험 신호, 확인 불가를 출처·시점과 함께 보여준다.
5. **Compose** — 가게 비교, 옵션, 요청사항, 주소를 확인해 장바구니를 구성한다.
6. **Confirm** — 최신 가격·품절·필수 옵션·총액을 재검증하고 사용자가 명시적으로 확인한다.

#### 세 가지 제품 원칙

- **질문은 줄인다**: 이미 아는 정보는 다시 묻지 않고 한 번에 한 가지 결정만 요청한다.
- **근거를 보인다**: 가격과 옵션은 원천 카탈로그, 식이 사실은 출처와 불확실성을 표시한다.
- **마지막 결정은 사용자가 한다**: 주소 저장, 주문 제출, 결제는 자동 실행하지 않는다.

## 06. 킬러 시나리오

### 한 문장이 근거 있는 주문으로 바뀐다.

#### 1. 요청

> “Something warm and mild like soto ayam. No pork, under 15,000 won.”

YOBI가 따뜻함, 국물, 낮은 맵기, 소토 아얌 유사 경험, 돼지고기 제외, 15,000원 이하를 구조화한다.

#### 2. 문화 설명

> “닭칼국수는 진한 닭 육수와 굵은 밀면이 들어간 한 그릇이에요. soto ayam보다 향신료는 적고 국물이 더 진하며, 맵기는 1/5입니다.”

#### 3. 식이 근거

- 가게 제공 정보: 닭고기·밀 표기
- 돼지고기: 가게 정보상 미표기
- 할랄 인증: 확인 불가
- 교차오염: 확인 불가

YOBI는 ‘먹어도 안전하다’고 단정하지 않는다. 위험 신호가 있으면 근거와 함께 경고하고 대체 메뉴를 제안한다.

#### 4. 비교와 구성

가게 2곳을 가격, 예상 배달, 양, 맵기, 포장 리뷰 축으로 비교하고 곱빼기·수저 옵션을 설명한다. “고수 빼고 최대한 덜 맵게”를 한국어 요청사항으로 양방향 미리보기한다.

#### 5. 최종 확인

메뉴·수량·옵션·요청사항·주소·배달비·총액을 한 카드에 표시한다. 사용자가 확인한 뒤 목업 결제를 실행한다.

> 시연용 가격·가게·리뷰 데이터이며 실제 요기요 운영 데이터가 아니다.

## 07. 핵심 기능과 차별성

### 번역기는 말을 바꾸고, YOBI는 주문 상태를 바꾼다.

#### 네 가지 핵심 능력

1. **Cultural Intelligence**: 메뉴를 직역하지 않고 맛·식감·조리법·양을 익숙한 음식 기준으로 설명한다.
2. **Dietary Evidence**: 식이 안전을 보증하지 않고 공식 정보·위험 신호·확인 불가의 근거 수준을 보여준다.
3. **Comparative Briefing**: 리뷰를 나열하지 않고 가격·배달·양·포장 등 같은 축으로 후보 차이를 요약한다.
4. **Order Action**: 최신 메뉴·옵션을 조회하고 요청사항·주소·장바구니를 구성하되, 쓰기 행동은 최종 확인 뒤 실행한다.

#### 기존 대안과의 차이

| 대안 | 문화적 음식 설명 | 식이 근거 상태 | 최신 가격·옵션 | 장바구니 행동 | 지속 선호 |
|---|---|---|---|---|---|
| 번역 앱 | 제한적 | 없음 | 없음 | 없음 | 없음 |
| 범용 LLM | 가능 | 실시간 검증 어려움 | 없음 | 없음 | 제한적 |
| 요기요 ChatGPT 앱(현재 공개 범위) | 추천·정보 확인 | 특화 정책 미공개 | 요기요 정보 | 요기요 앱/웹으로 이동 | 범용 대화 문맥 |
| YOBI | 사용자 선택 기준 | 출처·시점·불확실성 | 원천 재검증 | 확인 후 구성·연결 | 동의 기반 주문 선호 |

YOBI는 요기요 ChatGPT 앱의 복제본이 아니다. 현재의 대화형 탐색 방향 위에 **외국인 문화 지능, 식이 근거 정책, 지속 선호, 앱 안의 첫 주문 활성화 루프**를 더하는 제안이다.

## 08. Trust by Design

### AI의 확신이 아니라, 근거의 수준을 보여준다.

#### 식이 근거 3상태

1. **가게 확인**: 메뉴·가게가 제공한 공식 재료 또는 인증 정보. 출처와 갱신 시점을 표시한다.
2. **위험 신호**: 허가된 리뷰나 설명에서 제한 재료 언급이 발견됨. ‘추정’으로 표시하고 원문 범위를 제공한다.
3. **확인 불가**: 정보가 없거나 상충한다. 중증 알레르기 조건에서는 기본 제외하고 가게 직접 확인을 안내한다.

`safe=true` 같은 절대 안전 플래그는 두지 않는다. 할랄 인증, 원재료, 주방 교차오염을 서로 다른 항목으로 표시한다.

#### 행동 권한

- 자동 가능: 메뉴·리뷰 조회, 후보 설명·비교
- 사용자 확인 필요: 옵션 선택, 요청사항 번역, 장바구니 미리보기
- 자동 금지: 주소 저장, 주문 제출, 결제

#### 데이터와 보안

- 국적·종교를 AI가 추정하지 않고 사용자가 직접 선택한 식이 조건만 쓴다.
- 언어·식이 선호·주소 저장은 항목별 동의, 수정, 삭제를 지원한다.
- 공동현관 정보는 최소 보관·마스킹하고 감사 로그에 원문을 남기지 않는다.
- 리뷰와 가게 설명을 비신뢰 입력으로 처리하고 프롬프트 인젝션을 검사한다.
- 모든 도구 호출은 허용 목록, 입력 스키마, 결과 스키마, 감사 로그로 통제한다.

## 09. 기술 아키텍처

### LLM은 의도와 문화를 해석하고, 결정론적 주문 시스템은 사실과 거래를 검증한다.

#### Client

React/TypeScript PWA 또는 요기요 앱 내 선택형 대화 레이어. 다국어 채팅과 메뉴·근거·비교·장바구니 리치 카드를 제공한다.

#### Control Plane

Python/FastAPI, 세션 상태 머신, 필수 슬롯 검증, 정책 엔진, 액션 권한 제어, 구조화 출력 검증. 가격·품절·필수 옵션이 바뀌면 하위 선택을 무효화하고 다시 확인한다.

#### OCI AI

OCI Generative AI Responses API가 의도 해석, 음식 설명, 도구 선택과 응답 생성을 담당한다. Function Calling으로 애플리케이션이 정의한 조회·구성 함수를 요청하고, 실제 실행은 서버가 통제한다. OCI Guardrails로 프롬프트 인젝션과 PII 위험을 검사한다.

#### Tools

`search_menu` · `explain_food` · `dietary_evidence` · `compare_options` · `translate_note` · `validate_address` · `cart_preview`

#### Data & Integration

Oracle Autonomous AI Database에 카탈로그·동의 기반 선호·세션 상태·감사 로그를 저장한다. Oracle AI Vector Search는 사용권이 확보된 메뉴 설명과 리뷰의 의미 검색에 사용한다. Yogiyo Adapter는 MVP에서 동일 인터페이스의 Mock API를 호출하고, 상용화 시 실제 요기요 API로 교체한다.

#### 네 가지 기술 원칙

1. 가격·품절·옵션은 RAG가 아니라 원천 카탈로그가 답한다.
2. RAG는 음식 설명·리뷰 위험 신호에만 쓰고 `source_id`, `updated_at`, `status`를 붙인다.
3. 주문 제출·결제는 사용자 확인 뒤 기존 인증·결제 흐름이 담당한다.
4. 메뉴 설명은 캐시, 리뷰 브리핑은 배치 갱신해 실시간 LLM 비용과 지연을 줄인다.

## 10. 본선 4주 MVP

### 4주 뒤 보여줄 것은 기능 목록이 아니라, 3분 안에 끝나는 작동 경로다.

#### 범위 고정

- 영어 우선
- 서울 외국인 밀집 생활권 1개
- 검수 가게 30곳, 메뉴 약 150개
- 팀 자체 작성·동의 리뷰·사용이 허가된 정보 또는 합성 데모 데이터
- 실제 결제 대신 목업 결제
- 핵심 경로: 탐색 → 문화 설명 → 식이 근거 → 비교 → 옵션·요청 → 주소 확인 → 장바구니 확인

#### 일정

| 기간 | 마일스톤 | 작동 산출물 |
|---|---|---|
| 7/27~8/2 | M1. 찾는다 | OCI 환경, Mock Adapter, 상태 머신, `search_menu`, 데모 카탈로그 |
| 8/3~8/9 | M2. 이해하고 근거를 본다 | `explain_food`, `dietary_evidence`, 100문항 자체 평가셋 |
| 8/10~8/16 | M3. 주문을 구성한다 | 비교 카드, 옵션, 요청사항, 주소, `cart_preview`, 목업 결제 |
| 8/17~8/21 | M4. 사용자가 검증한다 | 외국인 8~10명 테스트, 오류·지연 개선, 시연 영상, 발표본 |

#### 일정 방어선

- **Must**: 문화 설명, 근거 3상태, 비교, 장바구니 확인의 닫힌 세로 슬라이스
- **Stretch**: 알림 역번역, “지난번처럼” 재주문, K-푸드 패스포트, SNS 공유
- 매주 작동 버전을 유지하고 Stretch는 Must 지표를 통과한 뒤에만 착수한다.

## 11. 검증 계획과 기대효과

### 외국인의 첫 주문을, 요기요의 반복 주문으로.

#### 본선 검증 설계

한국 거주 외국인 유학생·근로자 8~10명을 대상으로 동일한 주문 과업을 기존 번역 도구 병행 흐름과 YOBI 프로토타입에서 비교한다.

| KPI | 통과 기준 | 측정 방법 |
|---|---|---|
| 첫 주문 확인 과업 완료율 | 80% 이상 | 독립 수행 성공 비율 |
| 주문 확인 시간 | 중앙값 3분 이하 | 첫 발화~장바구니 확인 |
| 치명적 허위 안심 | 0건 | 식이 평가셋+로그 수동 검수 |
| 식이 사실 근거 연결률 | 100% | `source_id`·상태 존재 여부 |
| 가격·옵션 불일치 | 0건 | 카탈로그 스냅샷 대조 |
| 설명 이해도 | 5점 만점 4점 이상 | 과업 후 설문·회상 질문 |

#### 기대효과

- **Activation**: 번역 앱과 배달앱 사이를 오가던 첫 주문 이탈을 한 대화로 줄인다.
- **Retention**: 동의 기반 선호·주소·주문 이력으로 “the usual, same address” 재주문을 만든다.
- **Business**: 대학 국제처·외국인 지원센터·호텔 QR 제휴로 신규 유입 채널을 확보한다.
- **Platform**: 외국인에게 검증한 자연어 탐색·근거 기반 리뷰 브리핑·주문 도구를 내국인에게 확장한다.

#### 최종 제안

> YOBI는 외국인용 챗봇 하나를 더 만드는 아이디어가 아니다.  
> **요기요의 `Seamless` 전략을 모든 언어의 사용자에게 확장하는, 대화형 커머스의 첫 적용이다.**
